# Lina psycho bot

MVP Telegram-бота по [LIFE-50](https://linear.app/kamen-klinker-team/issue/LIFE-50/psihobot): предварительный набор участников психологического исследования Лины.

## Возможности

- `/start` сохраняет автоматически доступные Telegram-контакты, показывает временное описание и кнопку «Зарегистрироваться».
- Кнопка клавиатуры отправляет «Зарегистрироваться» сообщением от пользователя, сохраняя выбор в истории переписки, и подтверждает желание получить приглашение. После ответа клавиатура убирается. Это ещё не согласие на участие в исследовании. Кнопки регистрации в ранее отправленных сообщениях тоже продолжают работать.
- Повторные команды и нажатия сохраняют первоначальные даты и не создают дубликатов.
- `/stats` показывает общее число пользователей, число зарегистрированных и не подтвердивших регистрацию.
- `/participants` показывает обе группы по 5 пользователей на странице: имя, username, Telegram ID, статус, даты. Можно использовать кнопки или `/participants 2`.
- Административные команды и кнопки доступны только ID из `ADMIN_IDS`, только в личном чате.
- Администраторы учитываются как обычные участники, **если отправили `/start`**. Сам просмотр статистики не добавляет их в базу.

Сценарий исследования, анкета, рассылки, экспорт и веб-панель в эту версию не входят.

## Запуск на сервере через Docker

Готовы `Dockerfile`, `compose.yaml`, health check, постоянный volume SQLite и фрагмент конфигурации существующего nginx. Полный порядок настройки для `https://global.kolyach.me` — в **[deploy/README.md](deploy/README.md)**.

После заполнения `.env`:

```sh
docker compose build --pull
docker compose up -d --wait --wait-timeout 60
```

Внутренний порт контейнера — 3000; на хосте доступен только `127.0.0.1:3000`. Compose использует `APP_PORT` для изменения порта хоста и хранит SQLite в volume `lina-psycho-bot-data`. Node.js на сервере не требуется. Регистрация webhook выполняется отдельной командой после подключения nginx:

```sh
docker compose exec -T bot node scripts/set-webhook.js
```

## Запуск приложения

Нужен **Node.js 24 LTS, версия 24.14.1 или новее в ветке 24.x**. Внешних npm-зависимостей нет: HTTP, `fetch`, SQLite и тестовый раннер входят в Node.js. `node:sqlite` в Node 24 имеет экспериментальный статус и при запуске может выводить стандартное предупреждение Node; работоспособность проверена на Node 24.14.1.

1. Скопировать `.env.example` в `.env`.
2. Указать настоящий `BOT_TOKEN`, случайный `WEBHOOK_SECRET` и два Telegram ID в `ADMIN_IDS`.
3. Выполнить:

```sh
npm start
```

Проверки без Telegram-токена и внешней сети:

```sh
npm test
npm run test:coverage
```

Тесты используют временные SQLite-базы, подменяют исходящие вызовы Telegram и проверяют настоящий локальный HTTP-сервер. Реальный Telegram-бот при тестировании не вызывается.

### Переменные окружения

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `BOT_TOKEN` | Токен BotFather | Обязательна |
| `WEBHOOK_SECRET` | Секрет заголовка webhook, 1–256 символов `A-Z a-z 0-9 _ -` | Обязательна |
| `ADMIN_IDS` | Положительные числовые Telegram ID через запятую | Обязательна |
| `HOST` | Адрес прослушивания | `127.0.0.1` |
| `PORT` | HTTP-порт | `3000` |
| `DB_PATH` | Путь к файлу SQLite | `./data/participants.sqlite` |
| `APP_PORT` | Порт хоста для Docker Compose; внутри контейнера всегда 3000 | `3000` |
| `DISPLAY_TIMEZONE` | Часовой пояс дат в списке участников | `Europe/Moscow` |
| `WEBHOOK_URL` | Публичный HTTPS-адрес для отдельной команды регистрации webhook | Только для `webhook:set` |

Существующие переменные окружения имеют приоритет над `.env`. Относительный `DB_PATH` разрешается относительно рабочего каталога процесса. Все даты в SQLite сохраняются в UTC (ISO 8601).

Сгенерировать секрет можно локально:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

## Контракт для развёртывания

Docker-образ и Compose находятся в корне проекта; фрагмент nginx и инструкция развёртывания — в `deploy/`. Используется существующий HTTPS-блок nginx; DNS, TLS-сертификаты и VPN настраиваются на сервере отдельно.

- `POST /telegram/webhook` принимает JSON Telegram Update. Обязателен заголовок `X-Telegram-Bot-Api-Secret-Token`, равный `WEBHOOK_SECRET`. Неверный/отсутствующий секрет → `403`, неверный JSON → `400`, другой Content-Type → `415`, тело больше 64 KiB → `413`.
- `GET /healthz` проверяет доступность SQLite: `200 ok` или `503`. Секреты и данные пользователей не возвращает.
- HTTPS завершается на внешнем reverse proxy. Он должен передавать заголовок секрета и тело JSON. Его таймаут ответа должен позволять приложению завершить до двух исходящих запросов по 8 секунд каждый.
- В контейнере обычно требуется `HOST=0.0.0.0`. Публикацию порта ограничить loopback-интерфейсом хоста либо приватной сетью proxy; приложение не обеспечивает TLS самостоятельно.
- **Весь каталог `DB_PATH` должен быть постоянным volume/bind mount**, включая файлы `-wal` и `-shm`. Монтирования только одного `.sqlite` недостаточно. Каталог должен быть доступен для записи пользователю процесса. Файл вне постоянного хранилища не переживёт пересоздание контейнера.
- Запускать один экземпляр Node.js на одну базу. Дедупликация одновременных запросов рассчитана на один процесс.
- При `SIGTERM`/`SIGINT` приложение прекращает приём соединений, дожидается обработки текущих запросов и закрывает SQLite. Лимит завершения — 25 секунд; дать процессу не менее 30 секунд перед принудительной остановкой.

Приложение **не регистрирует webhook автоматически**. После настройки публичного HTTPS вручную выполнить с заполненным `.env`:

```sh
npm run webhook:set
```

Команда вызывает Telegram `setWebhook` с `WEBHOOK_URL`, `secret_token`, `allowed_updates: ["message", "callback_query"]` и `max_connections: 10`. Ожидающие события не удаляются. Стандартный адрес: `https://global.kolyach.me/telegram/webhook`. После смены секрета обновить конфигурацию приложения и повторить команду.

## Данные и обработка ошибок

Таблица `participants` хранит Telegram ID (первичный ключ), chat ID, полное имя Telegram, необязательный username, дату первого `/start` и необязательную дату регистрации. Статус вычисляется по наличию даты регистрации. Профиль обновляется при `/start` и подтверждении. Другие сообщения, групповые чаты и каналы не создают участников. При первом запуске схема создаётся автоматически, её версия хранится в `PRAGMA user_version`.

Для уже завершённых обновлений хранится только `update_id` и время обработки в `processed_updates`. Записи старше 7 дней очищаются при запуске и после каждой тысячи новых обработанных событий; участники при этом не удаляются. Порядок `update_id` не предполагается последовательным.

HTTP `200` возвращается после обработки. Сетевые ошибки, таймауты, `429`, ошибки Telegram `5xx` и внутренние ошибки → `503`, событие не помечается завершённым и может быть доставлено повторно. Постоянные ошибки отправки `400`/`403` журналируются и подтверждаются, чтобы не создавать бесконечные повторы. Истёкший ответ на callback (`400`) не мешает отправить подтверждение в чат. Успешно завершённые повторные события не отправляют сообщения заново даже после перезапуска.

Сохранение регистрации идемпотентно. Если процесс завершится между успешной отправкой Telegram-сообщения и записью `processed_updates`, повторная доставка может отправить ответ повторно; записи участников и даты останутся прежними. Транзакции SQLite не могут обеспечить однократную доставку исходящего HTTP-запроса.

Логи — JSON в stdout: события запуска/остановки и категории ошибок, числовые коды Telegram и названия методов. Токены, заголовки, сырые события, тексты ошибок внешних сервисов и сведения участников не журналируются.

## Перед публичным набором

Временные тексты находятся в `src/messages.js`. Лина должна утвердить окончательные формулировки, информирование о сохранении Telegram-контактов и порядок запросов на удаление данных. Пользовательского интерфейса удаления и команды `/stop` в этом MVP нет.

После развёртывания остаётся проверить на настоящем боте: `/start`, подтверждение и повторную регистрацию; команды от обоих администраторов и отказ обычному пользователю; сохранность данных после пересоздания контейнера. Приёмка серверной части LIFE-50 (HTTPS, VPS, совместимость с Amnezia) выполняется владельцем инфраструктуры.

## Код

- `src/config.js` — проверка конфигурации.
- `src/store.js` — SQLite и миграция схемы.
- `src/bot.js`, `src/messages.js` — сценарий и тексты.
- `src/telegram.js` — клиент Telegram Bot API с таймаутом.
- `src/server.js` — HTTP и дедупликация обновлений.
- `src/index.js` — запуск и завершение процесса.
- `scripts/set-webhook.js` — отдельная ручная регистрация webhook.
- `scripts/healthcheck.js` — проверка здоровья контейнера.
- `Dockerfile`, `compose.yaml`, `deploy/` — сборка и серверный запуск.
